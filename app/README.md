# 홍보공장 앱 (판매용 제품 · 1~4주차)

회사가 **회사 정보·브랜드 킷·AI API 키를 한 번 등록**하면, 캠페인(강의·행사) 1건의 팩트 시트로 카피 3안·카드뉴스·15초 릴스·AI 배경을 만들고 ZIP으로 내려받는 웹 서비스입니다.
사업기획서: `../docs/홍보콘텐츠플랫폼_사업기획서_20260928.docx`

## 진행 현황

| 기간 | 내용 | 상태 |
|---|---|---|
| 1~4주 | 회원·회사 프로필·브랜드 킷·팩트 시트, API 키 암호화 보관·연결 테스트, PoC 엔진 이식 | 완료 |
| 5~8주 | 인스타 광고(1:1·4:5·9:16 + 광고 문구), 상세페이지(860px 6블록), 자료(PDF·PPT) → 팩트 시트 초안, 광고 표현 검수, AI 생성 표시 | 예정 |
| 9~12주 | 요금제·결제, 이용약관·개인정보처리방침, 온보딩, 베타 10곳 | 예정 |

**1~4주 통과 조건 확인:** "로드 회사 계정으로 기존 키트 재현"
- 브라우저에서 가입 → 회사·브랜드·로고 → 실제 Claude·Gemini 키 등록(연결 테스트) → 인천시민대학 3차시 팩트 시트 → Claude 카피 3안 → Gemini AI 배경 → 2안·pop 템플릿 → 릴스(15.0초) → ZIP까지 한 번에 동작했습니다(약 65초).

## 실행

```bash
cd poc && npm install      # 렌더 엔진(카드뉴스·릴스·AI) 의존성
cd ../app && npm install
npm start                  # http://127.0.0.1:5180 (PORT, HOST로 변경)
npm test                   # 13건
```

- Node.js 22.5 이상 (내장 `node:sqlite` 사용)
- 데이터: `app/data/` (DB·회사별 로고·캠페인 파일). git에 올라가지 않습니다.
- 운영 환경 변수

| 변수 | 설명 |
|---|---|
| `APP_MASTER_KEY` | API 키 암호화용 32바이트 base64. **운영(`NODE_ENV=production`)에서는 필수.** 개발 중에는 `data/.master_key`에 자동 생성(권한 600) |
| `COOKIE_SECURE=1` | HTTPS 배포 시 세션 쿠키에 Secure 부여 |

## 구조

```
app/
├─ src/
│  ├─ server.js     라우트 (공개: 가입·로그인·메타 / 로그인 필요: 회사·브랜드·키·캠페인·파일)
│  ├─ db.js         SQLite 스키마 (users, companies, memberships, sessions, api_keys, campaigns, usage_log)
│  ├─ security.js   비밀번호(scrypt), 세션 토큰(DB엔 해시만), API 키 AES-256-GCM 암호화
│  ├─ providers.js  Claude·Gemini 키 연결 테스트(모델 목록 조회)
│  ├─ brand.js      회사 프로필·브랜드 킷 정리, 색상 대비 자동 보정, 금지 표현 검사
│  └─ http.js       라우터·쿠키·파일 전송
├─ public/          웹 화면 (로그인 · 캠페인 목록 · 캠페인 편집 · 회사·API 설정)
└─ test/            단위 6건 + 서버 통합 7건
```

렌더 엔진은 `../poc/src`를 그대로 씁니다(카피 `ai.js`, 카드뉴스 `cards.js`, 릴스 `reel.js`, AI 배경 `imagegen.js`, 템플릿 `templates.js`). 판매용으로 필요해 엔진에 추가한 것:
- `ai.js`: 회사별 브랜드명·말투(`voice`), 고객 키로 만드는 `anthropicClient(apiKey)`
- `cards.js`: 회사 로고(표지·신청 카드 오른쪽 위)
- `images.js`: 로고는 투명 배경을 살리도록 PNG로 정규화(`normalizeLogo`)
- `templates.js`: 템플릿별 색 조합(`themePairs`)과 대비 자동 보정(`fitColors`)

## 보안 설계

| 항목 | 구현 |
|---|---|
| 회사 간 격리 | 모든 캠페인·파일 조회에 세션의 회사 ID 조건. 다른 회사 ID로 요청하면 404 (테스트로 검증, 조건을 빼면 테스트가 실패하는 것까지 확인) |
| API 키 | AES-256-GCM. 회사 ID·공급자를 AAD로 묶어 다른 회사 행으로 옮기면 복호화 불가. 화면엔 끝 4자리만. 실제 키로 사용한 뒤 DB 파일에 원문이 없는 것 확인 |
| 키 전송 | AI사로는 헤더로만 전송(URL·로그에 남지 않음). 브라우저로 다시 내려보내지 않음 |
| 키 등록 | 저장 전 실제 연결 테스트 → 쓸 수 있는 모델을 함께 저장 |
| 비밀번호 | scrypt + 무작위 salt, 비교는 상수 시간 |
| 세션 | 무작위 토큰, DB엔 SHA-256만, HttpOnly·SameSite=Lax 쿠키, 14일 |
| CSRF | 상태를 바꾸는 API는 앱이 붙이는 `x-requested-with` 헤더 필수 |
| 로그인 | 같은 IP·이메일 15분에 10회 실패 시 429 |
| 업로드 | 사진·로고는 시그니처 확인 후 ffmpeg로 다시 인코딩(메타데이터 제거) |

## 설계 메모
- **DB는 SQLite(`node:sqlite`)로 시작:** 서버 없이 테스트가 돌고, 기관 설치형에도 맞습니다. SQL은 표준 문법만 써서 운영 배포(M3) 때 Postgres로 옮길 수 있습니다.
- **릴스 렌더는 서버 안의 순차 큐:** 워커를 여러 대로 늘릴 때(M3) Redis·BullMQ로 바꿉니다. 렌더 결과 상태는 메모리에 있어 서버를 재시작하면 카드뉴스를 다시 만들어야 합니다(파일·카피·표지는 유지).
- **팩트 시트는 현재 교육 행사용 필드**(강사·커리큘럼·혜택 등)입니다. 업종별 팩트 시트는 5~8주에 포맷과 함께 일반화합니다.
- **팀원 초대:** DB는 회사-회원 다대다(memberships)로 준비돼 있고, 초대 화면은 아직 없습니다.
